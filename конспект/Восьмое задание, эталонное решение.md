### Шаг 2. Обучили CatBoost и посчитали метрики

```python
from catboost import CatBoostRegressor

model = CatBoostRegressor(iterations=1000, verbose=0, random_seed=42)
model.fit(X_train_numerical, y_train)

y_pred = model.predict(X_test_numerical)

mape = mean_absolute_percentage_error(y_test, y_pred)
rmse = root_mean_squared_error(y_test, y_pred)
```

```python
print(f'MAPE: {mape}')
print(f'RMSE: {rmse}')
```

Разбор:
1. **Выбрали CatBoost**, а не xgboost или lightgbm. `CatBoostRegressor` — версия для регрессии (предсказываем число).
2. **Параметры:**
   - `iterations=1000` — сколько деревьев строит бустинг. 1000 — это и есть значение CatBoost по умолчанию, так что условие «по умолчанию» соблюдено;
   - `verbose=0` — не печатать лог обучения на каждой итерации;
   - `random_seed=42` — фиксирует случайность, чтобы результат повторялся.
3. **Данные те же, что в задании 6:** только `X_train_numerical` / `X_test_numerical` (`work_year`, `remote_ratio`). Метрики те же. Так модели можно честно сравнить.
4. Схема та же, что у линейной регрессии: `fit` → `predict` → метрики. Импорты метрик взяты из задания 6.

## Что в эталоне недосказано (стоит понимать самому)

1. **Почему мощная модель не помогла.** Бустинг умеет находить сложные нелинейные зависимости, но только если они есть во входных данных. Из двух признаков с 4 и 3 значениями получается максимум 12 комбинаций, то есть 12 групп строк. Лучшее, что может любая модель, — предсказать для каждой группы её среднюю зарплату. Линейная регрессия уже почти это сделала, поэтому разницы нет.
2. **Главный вывод: качество ограничено данными, а не моделью.** Если признаки бедные, смена алгоритма почти ничего не даёт.
3. **Гиперпараметры по умолчанию** — это нормальный первый шаг: сначала получаем базовый результат, потом уже настраиваем.
4. **Время обучения не замеряли.** Для честного сравнения с линейной регрессией полезно знать, что бустинг обучается заметно дольше. Здесь он не дал выигрыша в качестве, значит, пока дороже без пользы.

## Правило на будущее

- Чтобы сравнивать модели, держим одинаковыми данные, разбиение и метрики. Меняем только модель.
- Если сложная модель дала то же качество, что простая, проблема, скорее всего, в признаках, а не в алгоритме.
- Ставим `verbose=0`, чтобы не засорять вывод, и `random_seed`, чтобы результат повторялся.
- Разница в десятых долях процента — это «одинаково», а не «лучше».
