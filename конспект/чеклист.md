## 0. Прежде чем писать код

1. **Что угадываем?** Найди целевую переменную (target). У нас это `salary_in_usd`.
2. **Какой тип задачи?**
   - угадываем число (зарплата, цена) → **регрессия** → метрики MAE, RMSE, R²;
   - угадываем класс (да/нет, A/B/C) → **классификация** → метрики accuracy, F1, ROC-AUC.
3. **Есть ли описание данных?** Это эталон «как должно быть». Таблица показывает «как есть».
4. **Утечка (leakage).** По каждой колонке спроси:
   - будет ли у меня это значение в момент прогноза для нового объекта?
   - не является ли колонка замаскированным ответом?
   Если да — колонку убираем из признаков. Пример: `salary` + `salary_currency` → это и есть `salary_in_usd`, только в другой валюте.

## 1. Оценка качества данных (EDA)

Порядок всегда один, независимо от задачи:

| # | Что проверяем | Код | Что делать с результатом |
|---|---|---|---|
| 1 | Типы колонок | `df.dtypes` / `df.info()` | числа должны быть числами, текст — текстом (`object`) |
| 2 | Пропуски | `df.isna().sum()` | 0 → пишем «пропусков нет»; иначе решаем: удалить / заполнить |
| 3 | Дубликаты | `df.duplicated().sum()` и `df.duplicated(keep=False).sum()` | **не удалять сразу**, см. правило ниже |
| 4 | Ошибочные категории | цикл: `set(df[col].unique()) - set(допустимые)` | сверяем с описанием данных |
| 5 | Все текстовые колонки | цикл: `nunique()` + `value_counts()` | ищем опечатки и **редкие категории** |
| 6 | Общая сводка | `df.describe(include='all')` | смотрим min/max/среднее/самые частые |
| 7 | Выбросы | IQR + boxplot | нашли → проверяем правдоподобие → решаем |
| 8 | Логика между колонками | вручную | например: `salary` в разных валютах, сравнивать нельзя |

## 2. Правила принятия решений

**Удаление чего угодно (дубли, выбросы, строки):**
> Измерить → решить → объяснить. Никогда не удалять «по ощущению».

- Сравни распределение важных признаков **до и после** удаления (`value_counts(normalize=True)`).
- Удаляй во **временной копии** (`df_clean = df.drop_duplicates()`), основную таблицу не трогай, пока не решил.
- Если не уверен — оставь оба варианта и проверь на модели («с дублями / без дублей»).

**Дубликаты:**
- Нет уникального ID → нельзя отличить «двух реальных людей» от «одной записи дважды».
- Аргумент «за удаление»: копии попадут одновременно в train и test → завышенная метрика (утечка).
- Аргумент «против»: дубли могут быть реальными; удаление сдвигает распределение (у нас синьоров было 67%, стало 60%).
- `duplicated()` считает **лишние копии**; `duplicated(keep=False)` — **все строки, у которых есть близнец**, включая оригиналы.

**Выбросы:**
- Выброс бывает **ошибкой** (зарплата $5) → удаляем, или **редкой правдой** (учёный в США за $450k) → оставляем.
- Формула только находит подозрительных, решает человек.
- IQR: `Q1` (25%), `Q3` (75%), `IQR = Q3 - Q1`, выброс — за пределами `Q1 - 1.5*IQR` … `Q3 + 1.5*IQR`.
- **Деревья и бустинг устойчивы к выбросам**: они делят данные порогами, а не считают средние. Линейные модели — неустойчивы.

**Редкие категории:**
- Категория, которая встречается 1–2 раза, — модель по ней ничему не научится, это шум.
- На будущее: объединять редкие в `Other` или понимать, что на них модель будет ошибаться.

## 3. Гигиена кода

- Не вписывать числа руками (`1715 / len(df)`) — считать кодом (`df.duplicated(keep=False).sum() / len(df)`).
- Сохранять таблицу с `df.to_csv('data.csv', index=False)`, иначе появится мусорная колонка `Unnamed: 0`.
- В Colab ячейки выполняются в порядке нажатия ▶, а не по порядку на странице. Сомневаешься — «Среда выполнения → Выполнить все».
- `NameError: name 'df' is not defined` → не запущена ячейка с загрузкой.
- `FileNotFoundError` → файл не загружен в Colab (иконка папки слева → загрузить). После перезапуска Colab файлы пропадают.
- Перед проверкой значений смотри тип колонки: `0` (число) и `"0"` (текст) для Python — разные вещи.

## 4. Словарь

| Термин | Что это простыми словами |
|---|---|
| Библиотека | чужой готовый код, подключается через `import` |
| pandas / `df` | таблицы; `df` = DataFrame = таблица в памяти |
| NumPy | быстрая математика над массивами, на ней работает pandas |
| scikit-learn | инструменты ML: разделение данных, метрики, простые модели |
| CatBoost | бустинг: много маленьких деревьев, каждое исправляет ошибки предыдущих; сам понимает текстовые категории |
| train / test | на чём модель учится / на чём проверяем (она этих ответов не видела) |
| Переобучение | на train отлично, на test плохо — зазубрила, а не поняла |
| Утечка | модель подсматривает ответ через какую-то колонку |
| EDA | разведочный анализ — понять данные до модели |
| IQR | ширина «середины» данных, от 25% до 75% |
| Boxplot | ящик с усами: коробка — середина, линия — медиана, кружки — выбросы |
