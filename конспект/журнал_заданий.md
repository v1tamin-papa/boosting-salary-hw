## Задание 1. Проверка категорий на ошибочные значения

**Условие.** Проверить, что в категориальных признаках, у которых в описании перечислены значения, нет лишних. Написать цикл по признакам.

**Как решали мы.** Переписали допустимые значения из описания данных в словарь, циклом вычли из реальных значений допустимые:

```python
rules = {
    "experience_level": {"EN", "MI", "SE", "EX"},
    "employment_type":  {"PT", "FT", "CT", "FL"},
    "remote_ratio":     {0, 50, 100},
```

### 2. Зачем это задание
Модель учится на всём, что ей дали. Если дать ей колонку, которая содержит ответ, она покажет фантастическую метрику и будет бесполезна в жизни. Если дать мусор — будет учиться на шуме. Это последний фильтр перед обучением: **что именно пойдёт в модель**.

Вторая часть готовит следующий шаг: признаки с большим числом категорий — главная техническая трудность для модели (мало примеров на категорию, переобучение). От этого зависит, как будем их кодировать и почему выбран CatBoost.

### 3. Контекст из прошлых заданий

### 4. Термины
- **Признак (feature)** — колонка, которую модель использует, чтобы угадывать.
- **Целевая переменная (target)** — то, что угадываем. В признаки не входит.
- **Релевантность** — признак по смыслу может влиять на целевую и доступен в момент прогноза.
- **Утечка (leakage)** — признак, который содержит ответ или вычисляется из него.
- **Многокатегориальный признак (high cardinality)** — текстовая колонка с большим числом разных значений.

### 5. Как проверяем каждый признак (критерии)
Для каждой колонки отвечаем на 4 вопроса:
1. **Доступность:** будет ли значение у нового объекта в момент прогноза?
2. **Утечка:** можно ли из этой колонки (одной или вместе с другой) вычислить ответ?
3. **Смысл:** есть ли разумная причина, почему колонка влияет на зарплату?
4. **Информативность:** не почти ли константа? не дублирует ли полностью другую колонку?

Решение: «удалить» — если провал по 1 или 2. По 3 и 4 — это предмет обсуждения, решение с обоснованием.

### 4. Термины
- **Линейная регрессия** — модель вида `зарплата = a × год + b × удалёнка + c`. Подбирает числа `a`, `b`, `c` так, чтобы в среднем ошибаться как можно меньше. Рисует «прямую» через данные.

- **Коэффициенты** (`coef_`, `intercept_`) — найденные `a`, `b` и `c`. По ним видно, что модель «поняла».
- **RMSE** — корень из средней квадратичной ошибки. Измеряется в **долларах**. Сильно штрафует за крупные промахи.
- **MAPE** — средняя ошибка в **процентах** от настоящей зарплаты. В sklearn возвращается **долей** (0.25 = 25%).
- **Baseline «среднее»** — самая тупая модель: всем предсказывает среднюю зарплату по train. Если наша модель её не обгоняет — она бесполезна.

### 4. Термины
- **Кодирование (encoding)** — превращение текстовых категорий в числа.
- **OHE (One-Hot Encoding)** — каждая категория становится отдельной колонкой 0/1. «US» → колонка `country_US` = 1, остальные страны = 0.
- **LabelEncoding / OrdinalEncoding** — каждой категории присваивается номер: «EN» → 0, «EX» → 1, «MI» → 2, «SE» → 3. Номера по алфавиту, а не по смыслу.
- **Mean Target Encoding** — категория заменяется **средней зарплатой** людей этой категории в train. «US» → $155k, «IN» → $35k.
- **Кодировщик (encoder)** — объект, который выучивает правило кодирования (`fit`) и применяет его (`transform`).
- **Сглаживание (smoothing)** — для редких категорий среднее «подтягивается» к общему среднему, чтобы 1 человек не задавал значение категории.
- **Cross-fitting** — при target encoding train кодируется по частям: каждую строку кодируют средними, посчитанными **без неё**. Защита от утечки.

### 5. План шагов

- **2. LabelEncoding:** кодировщик на train → 8 колонок → линейная + CatBoost → метрики.
- **3. Target encoding:** кодировщик на train (с cross-fitting) → 8 колонок → линейная + CatBoost → метрики.
